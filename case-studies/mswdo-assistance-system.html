Capstone Project

MSWDO Financial & Medical Assistance Management System

A web-based management system for the Municipal Social Welfare and Development Office (MSWDO) of Bauang, La Union. Built as a capstone project to digitize the manual processing of financial and medical assistance requests across 46 barangays — replacing paper-based workflows with a role-based PHP/MySQL platform for Admin, MSWDO Staff, and 46 Barangay Health Workers (BHWs).

Project Overview

The MSWDO Assistance System digitizes the end-to-end workflow for assistance requests: BHWs register claimants per barangay, submit assistance requests with supporting documents (ID, certificates, medical records), MSWDO staff review and approve/deny, and the system generates weekly/monthly reports per barangay and assistance type. Covers 5 assistance categories: Medicine, Cash for Work, Educational Subsistence, Hospital Bill, and Burial Assistance.

Project Context

This was a college capstone project deployed locally for MSWDO Bauang, La Union. The system is not publicly hosted but the source code and database schema are available for review.

System Architecture & Roles

Three distinct user roles with dedicated dashboards and permissions:

  • Admin — User management (add/edit users), BHW-barangay assignments, view weekly/monthly reports across all barangays
  • MSWDO Staff — Review and approve/deny assistance requests, view claimant details, generate reports
  • Barangay Health Worker (BHW) — Register claimants, view assigned barangay, submit assistance requests with document uploads, view request status

46 barangays in Bauang mapped to individual BHW accounts (one BHW per barangay).

Database Design (MySQL/MariaDB)

Normalized schema with 7 core tables and foreign key relationships:

  • users — Authentication & roles (admin, mswdostaff, bhw)
  • bhw_assignments — BHW ↔ Barangay mapping (46 barangays)
  • claimants — Beneficiary profiles with demographics, category, documents
  • dependents — Claimant dependents with relationship, age, occupation
  • requests — Assistance requests with type, status, background case, proofs
  • weekly_reports — Aggregated stats per barangay/week/type
  • monthly_reports — Aggregated stats per barangay/month/type

Key Features

  • Multi-step claimant registration — Guardian details, beneficiary details, document uploads (ID, certificates, medical records)
  • 5 assistance types — Medicine, Cash for Work, Educational Subsistence, Hospital Bill, Burial Assistance
  • Document management — File uploads for ID pictures, certificates, claim proofs with organized storage
  • Role-based dashboards — Tailored navigation and actions per user type
  • Approval workflow — BHW submits → MSWDO staff reviews → Approve/Deny with status tracking
  • Automated reporting — Weekly/monthly reports with approved/denied/pending/released counts per barangay and assistance type
  • Session-based authentication — PHP sessions with role validation

Technical Implementation

Built with vanilla PHP 8.0 and MariaDB 10.4, deployed on local Apache (XAMPP):

  • PHP 8.0 (Procedural + Prepared Statements)
  • MariaDB 10.4 / MySQL
  • Prepared Statements (mysqli) for SQL injection prevention
  • File upload handling with move_uploaded_file()
  • Session-based auth with role checks
  • Responsive CSS with mobile breakpoints (750px, 550px)
  • Material Symbols icons, Google Fonts
  • .htaccess for basic routing/security

What I Learned

Building a real-world government system taught me that database design comes first — the 7-table schema with proper FK constraints saved countless refactoring hours. Prepared statements aren't optional; they're the baseline for any user input. Role-based UI is more than hiding menu items — each role needs its own workflow logic. File uploads require validation (type, size) and organized storage paths from day one. Reporting tables (weekly/monthly) denormalized for read performance was a practical trade-off I'd make again. The 46-barangay scope meant testing with realistic data volumes, not just happy-path samples.
